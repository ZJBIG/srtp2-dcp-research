一、结论先行
============================================================
1. 当前不是“只有想法”：relative importance、availability-aware bounded Prompt Adapter、direct-task continuous UtilityGate 已有代码、配置、训练阶段管理和测试。
2. 当前也不是“已证明有效的新方法”：本轮未核验到这条最终主线的完整、同协议、多 seed、严格测试集证据。根 README 明确说明正式训练与验证尚待完成；本地最新 smoke 的 hparams 是 2 epoch、每阶段只运行 2 batch，不能当正式收益。
3. 建议定位：在冻结 DCP 基座上，研究“任务效用监督的提示干预，以及干预幅度的样本级控制”，而非泛称“首次动态 Prompt”或“首次可靠性 Gate”。

3.2 当前可提炼的候选创新（代码存在 ≠ 新颖性/有效性已成立）
I1. 基于冻结任务损失差的 relative importance（A）
证据：reliability_learning.py:41-75、157-197；clip_missing_aware_prompt_module.py 的 reliability target 计算。
对完整样本，定义 delta_I=L_without_image-L_full、delta_T=L_without_text-L_full；r_I=sigmoid((delta_I-delta_T)/tau)，r_T=1-r_I。
价值：从只有 availability 类型的判断，向任务相关、样本级的相对模态偏好推进。
边界：共同的 L_full 相减抵消，实质为两种单模态路径损失的相对差。不是融合协同量，不是校准置信度，也不是因果效应的自动证明。
缺失样本的输出恒为 (0.5,0.5)，其监督被屏蔽，不能声称当前方法已学习到缺失样本的细粒度重要性。

I2. availability-aware bounded Prompt Adapter（A）
证据：reliability_learning.py:200-340，尤其 228-246、277-292。
机制：每层生成图/文残差，零初始化，按原 prompt RMS 构造 cap，并通过 tanh 限幅；显式输入 availability。
形式：P'_l=P_l+g*DeltaP_l；DeltaP_l=cap_l*tanh(raw_l/(cap_l+epsilon))。
价值：在原 DCP 解附近施加受限干预，g=0 提供回到基座的端点，缓解偏移失控。
边界：按元素限幅不是泛化理论保证；当前偏移从 [batch,1,dim] 广播到 prompt token，token 级分辨率有限。
缺失样本的 centered importance 为零，Adapter 的输入主要由缺失条件确定，因而同一缺失条件下其偏移没有来自 importance 的样本差异（cap 还依赖原 prompt）。

I3. direct-task continuous UtilityGate（A）
证据：reliability_learning.py:343-377；clip_missing_aware_prompt_module.py:650-664、875-901；config.py:314-335。
机制：Gate 读取 detached importance、availability 和冻结基座上下文，输出 [0,1] 连续强度；Gate 阶段通过最终任务 BCE 直接学习，不以五档 argmin 作为唯一监督。
价值：优化“是否/多大程度采用当前 Adapter”而非默认所有样本同幅干预。
边界：不能只用 Gate 输出有方差来证明有效；需要优于 g=1、validation-selected fixed、condition-only/context-only 和同条件 shuffled。

I4. 两阶段冻结与可解释归因工具（A）
阶段 1：训练 Predictor 与 Adapter，任务梯度与 importance 路径做隔离。
阶段 2：只训练 UtilityGate；基座、分类器、Predictor、Adapter 均冻结。
价值：能把“偏移是否有用”和“路由是否有用”拆开研究。
边界：这是有价值的训练/验证设计，但仅凭分阶段训练不足以构成独立顶会级新算法。

I5. 历史反事实代理博弈（A：代码；C：研究收益）
已有 counterfactual_proxy 分支及 pilot 记录，但当前正式配置 counterfactual_enabled=false。
作为后备方向保留，不建议同时合并进主线，以免重新引入监督与优化混杂。

四、代码与实验不足：按优先级处理
============================================================
P0-01【已复现】动态查询没有进入 checkpoint，基座恢复身份不完整
位置：clip/modules/vision_transformer_prompts.py:286-290、325-333。
三类 prompts_dynamic_* 是普通 Tensor，既非 Parameter，也非 buffer；它们实际参与前向，但不在 state_dict。
本轮以源码中的真实类做隔离小模型实验：seed0/seed1 构建后加载相同 state_dict，registered_state_equal=True，dynamic_keys_in_state=[]，dynamic_query_equal=False，最大差约 0.069515。
后果：两个模型即使 checkpoint 所有已注册张量一致，实际使用的动态查询仍可能不同；跨 seed、重新构建、baseline 与新模型初始化顺序都可能影响结果。
这不是本轮新增的代码问题，也尚未量化真实 CLIP 的指标影响；但足以阻止“严格相同冻结基座”的宣称。
修复方向：先恢复/追溯 legacy 初始化身份，明确其应是固定 buffer 还是可训练参数。固定查询应注册 persistent buffer；若改成 Parameter 则改变算法，必须作为新方法而非等价修复。无法恢复旧查询时重训可认证基线，不伪造旧状态。
验收：不同构建 seed、加载同一基座，固定输入在 eval 下的 query/prompt/feature/logit 一致；恢复前后 g=0 等价；真实模型测试覆盖。

P0-02【源码确认】best-fixed 在被评估 split 上现场择优
位置：tools/evaluate_final_reliability.py:148-184、493-495。
函数用当前 labels 选择最佳 macro-F1 gate 与最低 loss gate；当 --split test 时也一样。
后果：这是 test hindsight comparator，不是 validation-selected baseline。即使会让比较对象更强，也不能作为可部署、公平选择的 baseline 报告。
未发现这些 test 标签进入 learned Gate 推理；不要扩大表述为“整个模型训练泄漏”。
修复方向：在 validation 选择并保存 gate/threshold/checkpoint/selection_metric，再固定应用到 test；oracle 和 hindsight 独立命名、仅作为分析上界。不要在 test 看完结果后再选模型或调参。
验收：test 结果产物含 validation 决策文件哈希；更改 test 标签不会改变被选择 gate；训练/验证/测试数据 ID 隔离。

P1-03【源码确认】目前消融不能完整回答“连续 Gate 是否用到了样本重要性”
位置：evaluate_final_reliability.py:536-537 为全局 gate shuffle；195-207、675-685 对 importance -> gate 的来源消融使用 >=0.5 硬端点。
后果：全局 shuffle 同时破坏缺失条件匹配，领先它可能仅说明 condition 匹配有用。硬端点消融也不等于正式连续 Gate。
修复方向：增加 condition-preserving gate shuffle；分别测 importance-only/context-only/availability-only/neutral importance；使用原连续 gate 重新前向，并区分只干预 Gate 输入与同时干预 Adapter 输入。
验收：固定 seed 可复现；组内 gate 多重集不变；中间强度确实进入 encode_reliability_state，不被二值化。

P1-04【机制边界】relative importance 不是缺失场景下全面的可靠性估计
在 missing-both=0.7 时，完整样本理论上约 30%，只有这些样本贡献 relative 监督；实际比例以缺失表为准。
当前缺失样本 importance 恒中性，细粒度控制主要来自 Gate 的 context，而非 Predictor。
验收：完整/缺图/缺文分别报告增益；论文明确训练教师访问条件，不用隐藏模态或标签做部署推理；优先验证完整子集的 importance 独立价值。

P1-05【待量化】当前基线质量与证据链不足
默认 Original DCP 路径指向 epoch=3-step=507.ckpt，文件名不能证明模型欠拟合，也不能证明是收敛最优。
README 中“relative 相关性更好”“bounded Adapter 有效”属于历史摘要，本轮未独立复核原始数值。
需确认：完整数据训练步数、val 选择规则、早停条件、学习率、有效 batch、缺失表以及恢复身份。不得只比较不同预算、不同缺失表的 checkpoint。

六、下一步创新方向策划：一个主攻、一个备选
============================================================
方向 A【首选】以“提示干预收益/风险”替代单纯“模态相对重要性”作为控制目标
问题：relative importance 衡量两种单模态路径谁更好，却不必然预测这一次 Adapter 是否帮助最终任务。
假设：显式建模 A(x,g)=L_base(x)-L_adapt(x,g) 的收益曲线或收益符号，比仅用模态偏好更贴近控制目标。
最小方案：先保留现有 Adapter 和 continuous direct-task Gate，离线分析收益是否可预测；再加一个极小的 advantage head 或不确定性估计。保持模型容量/训练预算可比。
风险约束：以 validation 选择的阈值，允许预测收益不足时回退 g=0；用平均损失改善、负收益样本比例、最差组损失和 risk-coverage 而非只看 Gate 二分类准确率。
对照：现有 direct-task Gate、g1、val-fixed、context-only、condition-only、importance-only、random/condition shuffle、oracle（只做上界）。
成败条件：除整体 macro-F1/BCE 外，降低负迁移或高缺失组风险；在至少 3 seed 和跨缺失率下成立。
止损：若 matched-budget 的普通 context gate 已解释全部收益，不宣称 importance 创新；若 oracle headroom 很小，停止强化 Gate，先改善 Adapter。
成本：中；复用 signed_gate_offline 和 export_signed_gate_cache；先诊断再写新损失。
新颖性边界：advantage/不确定性/回退都不是新词，贡献必须体现在提示干预的任务定义、可验证风险控制和缺失泛化上。

方向 B【第二优先】缺失机制漂移与模态退化联合鲁棒性
问题：当前默认 MCAR 式随机缺失率，不等于真实部署中类别/质量相关的缺失；模态“存在”也不等于“有用”。
假设：availability 与质量/效用分开建模，在训练/测试缺失分布不一致以及图像/文本退化时更稳。
最小方案：不先改模型，建立 missing rate/type shift 与轻量模态质量退化评估；只有暴露真实失败后，再研究分组稳健优化或质量条件 Gate。
实验：train missing-both 0.7；val/test 在 0、0.3、0.5、0.7、0.9、1.0 缺失率与缺图/缺文/混合条件下评估。1.0 仍是每样本至少一种模态可用。
扩展：基于输入可观测质量构造缺失倾向；基于标签的 MNAR 仅是研究压力测试，标签不得成为推理输入。每种生成机制明确记录。
指标：宏/微 F1、BCE、按缺失条件的最差组、退化曲线面积、方差、必要时 Brier/ECE（多标签定义须固定）。
风险：只增加 benchmark 可能不足以成为算法创新；应与方向 A 结合而非另堆多个适配模块。
成本：中；优先作为主线的外部有效性验证。

方向 C【备选】显式建模模态协同/冲突而不是相对优劣
问题：delta_I-delta_T 抵消 L_full，无法表示“两个都重要”或“组合互相冲突”。
最小假设：同时保留 absolute delta、relative difference，再加入协同项 S=L_I+L_T-L_IT-L_empty；在冻结模型的定义下分析其与干预收益的关系。
S 的符号只在固定损失定义下解释：S>0 表示联合观测的损失改善超过两种单独改善之和。
实验：relative-only、absolute-only、relative+absolute、加协同项、标签打乱/同条件打乱控制；先看教师可预测性，再看最终任务收益。
风险：L_empty 的全零输入不是自然样本，prompt 路径切换也改变计算机制；因此只能叫 operational counterfactual utility，不直接上升为可识别的真实因果效应。
成本：中高；训练教师开销更大；完整样本不足会造成监督覆盖瓶颈。

方向 D【后置】模态/层级细粒度 Gate 与预算感知控制
问题：一个样本一个 g 同时控制所有层与两个模态，可能掩盖层间/模态间最优干预差异。
最小方案：先 2 个模态 Gate 或 2 段深度 Gate，再考虑低秩分解 g_(l,m)，保持总偏移范数与额外参数预算一致。
对照：单 Gate、仅增加相同参数 MLP、随机层 Gate、各层固定 gate、低秩 Gate；报告推理代价。
风险：参数增加导致表面涨点；只有超过 matched-budget control 才有研究意义。
成本：中；必须等方向 A 的单 Gate 有效性确定。

方向 E【暂缓】反事实代理博弈、生成补全或大规模记忆库
理由：已有 counterfactual_proxy 分支可用，但它引入优化稳定性、教师/补全偏差和额外文献重叠；当前主线证据尚未闭环。
仅当高缺失条件明确受限、且简单改进失败后，另开分支与独立协议，不覆盖本次归档主线。

建议选择：先完成当前主线的可靠评估，以 A 为方法主攻、B 为泛化验证；C/D/E 不并行堆叠。

七、实验设计与论文判定规则
============================================================
7.1 先锁定基座和数据
- 修复/认证完整基座状态，记录代码 commit、基座 SHA256、CLIP SHA256、Arrow/sample-ID 哈希和 missing table 哈希。
- 训练集拟合，验证集选 checkpoint/gate/阈值/超参数；方案冻结后只做一次正式测试集报告。
- 共同基座的添加模块增益与整个 pipeline 多 seed 分开报告；不能把同一基座下 3 次头部训练当成 3 个完整独立 pipeline。
- 标注训练预算：base epoch、adapter epoch、gate epoch、optimizer steps、有效 batch、数据规模及 GPU 时长。

7.2 最小消融矩阵
E0 Original DCP/g=0：基座身份与独立 baseline 一致。
E1 bounded Adapter + g=1：回答 Adapter 是否有用。
E2 bounded Adapter + validation-selected fixed g：排除全局强度调优收益。
E3 完整 learned continuous：正式方法。
E4 condition-preserving shuffled gate：排除缺失组分布解释。
E5 availability-only Gate、context-only Gate、importance-only Gate：剥离信息来源。
E6 predicted vs neutral vs condition-prior vs condition-shuffled importance：分别只干预 Gate、只干预 Adapter、同时干预；连续前向。
E7 bounded vs unbounded、availability on/off、relative vs absolute：控制参数和优化预算。
E8 oracle importance/oracle gate：仅分析上界，不参与可部署成绩排名。
E9 SyP-style contextual multiplicative prompt adapter 或可复现官方方法：同主干、同数据、同预算比较。

7.3 统计与指标
- 先完整 seed0 排错，再 seed1/2；最低报告 3 seed 均值与标准差，资源允许扩至 5 seed。
- paired 比较使用相同样本 ID、相同缺失表；bootstrap 对样本成对重采样并重算 F1，不对 F1 做错误的逐样本加和。
- 同一训练 seed 评估多个 missing seed 时，分开报告两种方差；置信区间不要混成伪独立样本。
- 主任务 MM-IMDb：macro-F1 为主要指标，micro-F1/BCE 为辅助；完整/缺图/缺文分组，另看稀有类别。
- 诊断：importance 相关性与覆盖、Gate 分位数/方差/饱和率、偏移与原 prompt 范数比、负收益比例、oracle headroom。
- 工程：可训练参数、完整训练成本、推理延迟、峰值显存；报告测量设备与 batch。

7.4 结果解释与止损规则
- E1>E0，E3 不优于 E2/E4：只支持 Adapter，不支持样本级 Gate。
- E3>E2，但去掉 importance 不降：支持 contextual routing，不支持 importance 驱动路由。
- importance 能预测教师但最终任务不改善：只能报告表征/诊断发现，不能宣称实用增益。
- 所有方法只在单一缺失表/单 seed 改善：属于不稳定先导证据。
- oracle 也不明显优于 E1：Gate 可挖掘空间不足，先优化 Adapter 或基座。
- 真实补全/额外标签只允许作为训练教师或明确 oracle，不进入正式 test 推理。

九、建议的论文结构与当前措辞限制
============================================================
题目备选（暂定，不能视为最终新颖性结论）：
“面向模态缺失的任务效用驱动有界提示适配与连续干预控制”
“Task-Utility-Aware Bounded Prompt Adaptation under Missing Modalities”

结构：
1. 问题：缺失类型条件化不足以解释样本级提示干预效用。
2. 方法：基座身份、relative/utility 定义、有界残差、连续强度、两阶段优化。
3. 实验：先 Adapter 再 Gate 再 importance 的归因链；严格 validation/test 协议。
4. 鲁棒性：缺失率/类型/机制/质量偏移与第二数据集。
5. 局限：教师监督覆盖、效用与真实因果的区别、额外前向成本、基座依赖。

目前可用：“已实现”“提出候选框架”“待验证”“在指定条件下开展实验”。
目前不可用：“首次”“SOTA”“显著提升”“有效恢复缺失语义”“因果可识别”“所有 seed 均有效”，除非有相应新颖性审查与实验证据。

本文件为后续工作的验收清单，不替代正式训练结果；本轮没有修改模型源码或跑完整训练。
